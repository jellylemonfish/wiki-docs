    Shien's AI Infrastructure Wiki

    这是一个记录我从数学与统计背景转向 AI Systems / AI Infrastructure 的工程实践 Wiki。

    这个项目关注的并不只是“如何调用一个大模型”，而是一个更完整的问题：

    如何把一个 AI 能力，从模型调用变成一个真正可以访问、部署、运行、维护和迭代的服务？

    从 Linux 服务器、网络与反向代理，到 FastAPI、Docker、日志、公网访问，再到 LLM API、RAG 知识库和后续的 GPU 推理服务，本 Wiki 持续记录整个 AI 服务系统从零搭建的过程，以及其中的技术决策、故障排查和工程实践。

    • GitHub：@jellylemonfish
    • 简历 / CV【2026.08 更新】

    所以，这个项目到底在做什么？

    我的原始背景主要来自数学与统计。在学习 LLM 相关理论与应用的过程中，我逐渐开始关注模型之外的问题：一个模型在 notebook 里能够生成回答，它能成为一个服务吗？答案是不能的。……从 Demo 到真正运行的系统，中间还存在服务器环境、网络API、进程管理等等大量工程问题。

    因此，我从一个主要使用 R 进行统计计算、具备 Python 数据处理经验的研究背景出发，从零开始搭建一套完整的 AI 服务环境。目前已经完成了基础 Infrastructure、LLM API 服务接入，以及第一版可运行的 RAG 工程文档问答系统。

    这个 Wiki 不只记录最后怎么做，也记录在开发过程中遇到的 * 为什么选择这种方案； * 系统中的不同组件分别解决什么问题； * 实际开发过程中出现过哪些 bug； * 如何定位和解决这些问题； * 系统目前有哪些限制，以及下一步准备如何继续改进。 * ……等等。

    目前系统仍然使用外部 LLM API 作为部分推理后端，但整体架构已经按照服务化方式拆分。后续将进一步进入 vLLM + GPU 本地模型部署、性能 benchmark、profiling、并发与资源管理 等阶段。

    当前系统架构

    目前项目主要由三个部分组成：

    • wiki-docs：工程技术文档，同时也是 RAG 的知识库来源；
    • rag：负责文档处理、向量索引、检索和上下文增强；
    • fastapi-demo：负责对外提供 AI 服务接口。

    当前已经跑通的主要链路如下：

                             GitHub Pages
                              |
                           Chat UI
                              |
                       Tailscale Funnel
                              |
                           FastAPI
                              |
                         RAG Service
                              |
              +---------------+---------------+
              |                               |
          Retriever                         LLM API
              |
           Chroma
              |
          Embeddings
              |
      Markdown Wiki Docs

    其中，Wiki 文档首先经过切分、Embedding 和索引构建写入 Chroma；用户通过 Chat UI 提问后，FastAPI 调用 RAG 服务检索相关文档，将检索结果作为上下文交给 LLM，并最终返回基于工程文档生成的回答。

    当前版本仍属于系统演进的早期阶段。接下来将继续进入 GPU 推理服务和本地模型部署、性能测试与更完整的 AI Infrastructure 实践
