    反向代理与服务入口管理：Nginx

    在【网络基础与请求链路】小节中，我们理解了IP可以定位服务器，端口可以定位程序。但如果生产环境直接暴露了网络服务的端口的画，则会存在安全与管理问题。因此，我们需要在应用前增加一个统一的入口：Nginx。

    Nginx负责接收公网请求，再转发给内部应用。

    Date: 2026-08-09 22:30:00

    1. 什么是nginx？

    Nginx 是一个高性能 Web Server 和反向代理服务器。它主要负责直接响应HTTP请求（例如返回静态网页）和把用户请求转发给后端服务两个职责。

    2. Nginx排查流程

    • systemctl status nginx 确认是否active runing，如果不是执行 sudo systemctl start nginx
    • 确认本机curl curl http://127.0.0.1 ，正常情况下应该包含<title>Welcome to nginx!</title> 这句。如果本机curl不通，是nginx的问题。
    • 若正常，继续检查端口ss -tlnp | grep :80
    • 可能问题是在云服务商的设置里。比如阿里云的安全组，阿里云>控制台>云服务器ECS>安全组>入方向>添加规则,http（80）https（443）
    • 可以通过日志排查。日志指令如下：
    systemd日志:
journalctl -u nginx

Nginx请求日志:
sudo tail -f /var/log/nginx/access.log

Nginx错误日志:
sudo tail -f /var/log/nginx/error.log

    3. 配置反向代理

    经过前面的步骤，Naginx已经能够返回 Welcome to naginx 页面，但这并非我们的真正目的。我们希望能够达成“负责接收公网请求，再转发给内部应用”的这个步骤。

    • 修改 /etc/nginx/sites-available/default文件，将原本的路劲修改，便可以完成转发。
    location / {
    try_files $uri $uri/ =404;
}
# 修改成
location / {
    proxy_pass http://127.0.0.1:8000; #端口可以根据server修改对应的端口。这里的案例server是fastapi，所以设定转为了对应的端口8000
}
    • 补全配置检查和reload。生产环境修改配置不会直接重启，故我们先做一个检查nginx -t检查文件语法，避免配置改错导致整个nginx运行出现问题。确定没有问题之后，systemctl reload nginx手动重启。

    在配置的过程中，访问公网IP可能会出现 HTTP 503这样的Nginx正常，但后端不正常的情况。用户请求已经到达 Nginx，但是 Nginx无法获得后端响应。排查过程如下。

    1. curl http://127.0.0.1:8000 在本地终端确认对应的服务是否存在运行问题。
    2. sudo nginx -T | grep -A 5 "location /" 检查配置文件中对应的转发路径配置proxy_pass http://127.0.0.1:8000;
    3. sudo nginx -T | grep listen 检查配置文件中对应的监听配置 listen 80 default_server;
    4. 以上都没有问题，检查虚拟服务器vps的安全组是否开放了HTTP和HTTPS协议的80端口和443端口。
    5. 也有可能是浏览器的VPN缓存问题。刷新多几次就好。

    4. 请求头与生产配置

    我们在这里继续修改 /etc/nginx/sites-available/default文件，配置好我们的生产环境。往往最简单的生产环境配置大致如下：

    server {

    listen 80 default_server;

    location / {
        proxy_pass http://127.0.0.1:8000;

        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }

}
    • proxy_set_header Host $host; :告诉server 用户原本访问的地址是什么。例如，若用户访问的为http://example.com，那么Naginx转发给server则会保留Host: example.com 。
    • proxy_set_header X-Real-IP $remote_addr; 保存真实客户端的（公网）IP。
    • proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for; 记录经过了哪些代理，记录完整链路。
    • proxy_set_header X-Forwarded-Proto $scheme; 告诉后端，用户用的原协议是HTTP 还是HTTPS 。
