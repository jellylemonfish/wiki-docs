    网络基础与请求链路

    在部署AI服务时，程序不仅需要运行在服务器上，也需要被外部用户访问。在FastAPI服务部署的过程中，我们是通过公网IP8000 或者 VS code Remote SSH访问服务。在本文档中，我们将会了解到，一次浏览器请求如何从用户电脑出发，通过互联网到达云服务器，并最终找到服务器中的某个程序。

    Date: 2026-08-04 18:09:52

    1. 一次HTTP请求需要经过什么过程

    网址访问：http://公网IP:8000/docs 实际上包含三个层次的定位：IP（目标服务器地址，找到哪台服务器，公网IP），端口（目标服务监听端口，找到服务器上的哪个程序，8000）和路径（具体访问路径，找到程序提供哪个功能，/docs）。http 表示使用HTTP协议进行通信。

    2. IP地址

    IP地址负责网络中的设备定位。而服务器本身，可能拥有多个地址。

    • 公网IP： 外部用户通过公网 IP 找到云服务器。例如：http://47.xxx.xxx.xxx:8000，这里的 47.xxx.xxx.xxx 便是服务器对外暴露的地址。
    • 内网IP： 内网 IP 只在局部网络中有效。例如 192.168.1.5。不同家庭可能同时拥有相同的内网IP，因为它们处于不同的网络环境。
    • 127.0.0.1: 127段是回环地址。它表示“设备自行访问自己这台设备”。比如指令curl http://127.0.0.1:8000/docs 表示要求服务器自己访问自己的 FastAPI 服务。
    • curl 可以模拟客户端发送HTTP请求。如果成功，说明路由正常，Uvicorn正在运行，和对应的服务加载成功。但curl本质上是模拟，并不代表公网访问请求一定成功。

    3. 数据如何找到服务器

    浏览器发送请求之后，数据是不会直接链接到服务器。往往的过程是：个人设备数据传送到家庭路由器，路由器接入运营商网络，向互联网中的多个路由器传送数据，最后成功到达目标服务器。路由器的工作就类似快递中转站：每个路由器只需要查看目标IP，然后就能根据自己的路由表决定数据下一步要传输到哪里。

    • 网络中的数据会被拆分为多个数据包传输。如果部分数据包在传输过程中丢失，则称为丢包。TCP 会通过确认机制和重传机制保证可靠传输。
    • 请求和响应不一定要经过完全相同的路径。

    个人设备数据能够传送到家庭路由器、意味着多个设备可以共享一个内网IP的原因是NAT（Network Address Translation)。设备内网经过路由器转入公网的时候，路由器本身会记住这条链接。服务器返回数据之后，路由器根据记录把响应交回正确设备。

    一次浏览器的访问往往会使用多种协议，如HTTP -> TCP -> IP -> 网卡。 HTTP负责应用之间如何交流，TCP保证可靠运输，IP负责跨网络找到目标设备，网卡负责实际发送与接收数据。

    4. DNS：域名如何找到IP

    在前面的网络访问案例中，我们一直使用直接用IP地址访问服务器的方式 http://47.xxx.xxx.xxx，但在真实互联网中，几乎没有人能长期记住IP地址。IP存在可能变化（云服务器重装、迁移）与不适合扩展（一个服务可能对应多个IP）这样的问题。

    因此，我们需要一个更符合人类直觉的访问方式：用名字访问，而非用数字访问。 如https://example.com， 这里的example.com 便是一个域名。浏览器将域名转换成公网IP的方法便是采用DNS (Domain Name System)。

    当用户在访问http://example.com的时候，实际上浏览器在后端查询DNS系统，得到对应的IP地址建立网络连接。

    5. 端口

    一台服务器可以同时运行多个服务，每一个网络服务都会监听某个 IP 地址和端口组合。可以理解成：IP是楼栋地址，端口是楼里的房间编号。Linux会根据目标端口，将请求交给监听该端口的程序。

    一个网络程序如果想要监听某个端口、接收请求，则需要向Linux注册socket。socket 是程序和 Linux 网络系统之间的接口。例如该指令：uvicorn main:app --host 0.0.0.0 --port 8000，就表示“我要监听 8000 端口，等待进入的请求。” Linux内核在读取目标IP和端口后，便会寻找对应的socket，交给对应的进程。Uvicorn便才能处理http请求。

    • 在程序停止后，端口通常会被释放。
    • 如果两个程序同时监听一个端口就会发生冲突，Linux无法判断请求应该交给哪个程序。
    • 程序本身不会直接接收网卡数据。

    6. 一些常见的故障

    Connection refused：服务器找到了但没有程序接受链接。可能服务没有启动，或端口设置错误。

    Connection timeout：请求没有成功到达服务。安全组没有开放端口，或者请求被防火墙阻挡。需要确认云服务商的相关入口/出口设置。
