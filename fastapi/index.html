    API服务开发与部署：FastAPI

    在在【反向代理与服务入口管理：Nginx】中，我们实现了公网请求经过Nginx转发到内部服务。真正处理业务逻辑的是后端应用服务。在过往的文章中，我们经常提及的server案例是FastAPI，在本文将简略介绍该服务。我们将通过其构建一个Python Web网络服务，并理解其启动、部署 排查的流程。

    Date： 2026-08-10 13:37:28

    1. 什么是FastAPI和Uvicorn

    FastAPI是基于Python的现代Web框架，用于快速构建API服务。它负责定义接口路由、解析请求数据、执行对应业务逻辑，并生成响应。FastAPI本身不会监听网络端口。为了让FastAPI应用能够接收HTTP请求，需要使用ASGI服务器，例如Uvicorn。

    Uvicorn负责接收网络请求，并将请求交给FastAPI处理；FastAPI负责根据请求内容决定调用哪段业务逻辑。FastAPI像漫画内容本身，决定故事应该如何展开；Uvicorn像出版社和发行渠道，负责让读者能够找到这本漫画，并把读者请求传递给作者。

    在生产环境中，FastAPI不会直接暴露在公网，而是在内部端口运行，并由Nginx作为接收请求的入口代理。

    2. Python虚拟环境

    在完成程序的脚本中，我们往往在虚拟环境中执行这些脚本。构建虚拟环境的指令如下：

    python3 -m venv .venv       # 构建虚拟环境
source .venv/bin/activate   # 进入虚拟环境

    因为不同的项目可能需要不同版本的环境以来，如果直接安装到系统python中，就会产生依赖冲突。我们通过构建虚拟环境、并在它们内部运行程序，有助于隔离python解释器和第三方库。

    4. Uvicorn的监听

    启动ASGI服务器并监听指定地址和端口的指令类似：uvicorn main:app --host xxx.x.x.x --port xxxx。特别的，若指令为uvicorn main:app --host 127.0.0.1 --port 8000该服务只绑定服务器自身的回环接口（loopback interface），因此只能由服务器内部访问，公网请求无法直接访问该端口。若指令为uvicorn main:app --host 0.0.0.0 --port 8000表示监听服务器所有网络接口。如果安全组和防火墙允许，则内网或公网均可能访问该端口。

    在我们的生产环境中，因为我们已经实现让公网请求Nginx转发到内部服务，故所有通过HTTP/HTTPS访问该服务器的请求，会首先到达Nginx监听的80/443端口。Nginx读取请求里的 Host，然后匹配对应的 server block，再执行对应的 proxy_pass。这部分的网络配置详见Nginx小节。
