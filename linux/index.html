    Linux 系统环境与服务管理

    Linux是现代 AI infrastructure的基础运行环境。在AI服务的部署中，Linux 负责提供计算环境、进程管理、权限控制以及服务生命周期管理。

    本文记录在云服务器部署服务过程中涉及的 Linux 基础知识，并涉及部分实践过程和个人兴趣产生的深入学习笔记。

    Date 2026-08-03 17:14:19

    1. Linux Server Enviroment

    在实际部署 AI 服务时，通常不会直接运行在个人电脑，而是在远程 Linux 服务器上。

    本项目使用阿里云 ECS 作为部署环境，通过 SSH 远程连接服务器。（阿里云相对于其他国内云厂商，有专门面向个人学习者的包年优惠）

    主要环境为： - OS: Ubuntu Linux - Remote access: SSH - Development tool: VS code remote SSH

    常有的环境检查命令

    whoami              # 当前用户
pwd                 # 当前目录
hostname            # 当前主机名
cat /etc/os-release # 操作系统信息
uname -a            # 内核和架构
free -h             # 内存
df -h               # 磁盘

    2. SSH remote access

    Secure shell(SSH)是一种用于远程登录服务器的协议。其他类型的协议可以在网络篇章检索。通过SSH，我们可以让云服务器远程执行我们的命令、管理服务器的文件和部署应用程序。

    • 在本地开发环境中，可以配置SSH key的认证减少频繁输入密码的繁琐。数字key有很多种类型，如SSH中经常配置的rsa key，也有如配置github的ed25519 key。
    • 在本地开发环境中，尽量使用普通用户运行服务。root有完整权限，但并不建议日常运行使用。避免长期使用root用户，降低误操作的风险，也能更好的符合生产环境的实践。

    3. Process 与 Service Management

    Linux 中，一个正在运行的程序实例通常表现为一个 Process。例如，我们的FastAPI-demo 程序脚本main.py里的 FastAPI 应用需要由 Uvicorn 这个 ASGI Server 启动并对外提供服务。但是，直接运行uvicorn main:app --host 0.0.0.0 --port 8000 是有临时性的，SSH退出之后，对应的服务就会停止；服务器重启之后也不会自动启动。所以，面对这样的情况，我们需要 Service Manager。

    在现代 Linux 发行版中，systemd 是最常见的 Service Manager 和 init system。它负责启动与停止服务，自动重启与开机启动，和日志的管理。在有Service Manger的情况下，我们的运行结构将会变成：

    User #创建.service文件
->systemd -> Application Process -> uvicorn -> FastAPI application (main:app)

    也就是说，Uvicorn 负责运行应用，systemd 负责管理 Uvicorn。

    .service 文件是告诉 systemd 如何运行程序的配置文件。简略的配置内容如下：

    [Unit]
Description=FastAPI Demo Service
After=network.target 
#告诉 systemd，等网络准备好以后再启动这个服务。因为 FastAPI 要监听端口，没有网络当然没法工作。


[Service]
User=shien #指定非root用户
WorkingDirectory=/home/shien/fastapi-demo
ExecStart=/home/shien/fastapi-demo/.venv/bin/uvicorn main:app --host 0.0.0.0 --port 8000 
# ExecStart：把进入虚拟环境的命令自行合并了。
##  source .venv/bin/activate
##  unvicorn main:app --host 0.0.0.0 --port 8000
# 不过，因为 .venv/bin/uvicorn 本身就是虚拟环境里的 Uvicorn，所以直接调用它，就相当于已经进入了虚拟环境，不再需要 source activate。
Restart=always #设置自动重启


[Install]
WantedBy=multi-user.target
# WantedBy：这一行告诉 systemd，当系统进入正常运行模式时，希望这个服务也自动启动。

    4. systemctl 管理服务

    systemd 是后台真正负责管理服务的管家，那systemctl 是用户和这个管家沟通用的工具。常见的命令如下：

    systemctl daemon-reload      #重新加载配置
systemctl start fastapi-demo #启动，后面的application换成需要的
systemctl status fastapi-demo #查看状态
systemctl stop fastapi-demo   #停止
systemctl restart fastapi-demo #重启
systemctl enable fastapi-demo #开机启动

    5. 排查流程

    实际服务器服务异常的问题，要先检查状态(systemctl status)，再查看日志(journalctl -u)确认问题。修改完配置之后，再重新加载配置(systemctl daemon-reload)并重启。日志查看的常见命令如下：

    journalctl -u fastapi-demo #查看日志
journalctl -u fastapi-demo -f #实时查看，建议配合新开一个terminal配合使用
journalctl -u fastapi-demo -n 50 #最近50条日志，适合用来追溯+缩小范围

    在排查过程中，可能会出现因错误服务自动重启导致内存溢满等连带问题。此时登录云服务商的对实例进行重启，再需通过VNC远程登录修改配置，避免SSH多次触碰重启机制。
